# JobDeck Quiet UI 设计规范

> 状态：正式规范（Normative）  
> 版本：1.0  
> 更新：2026-08-25

JobDeck 是面向技术求职者的 AI 求职操作台，不是营销落地页。界面首先要让用户快速看懂：Agent 正在做什么、已经完成什么、为什么暂停、下一步是否需要本人决定。

这份文档是 Web 工作台、Chrome 扩展和后续新增页面的统一设计依据。实现中的颜色、字号、间距、圆角和动效必须优先使用 `design-tokens.css`，不得在业务组件里重新发明一套视觉语言。

## 1. 设计原则

1. **默认安静**：普通信息使用中性色，强调色只用于当前状态和主要操作。
2. **一屏一件事**：每个区块最多一个实心主按钮；其他动作使用次级按钮或文字链接。
3. **状态决定结构**：运行中、等待确认、失败和完成必须在原位置呈现，不依赖临时 Toast 才能理解。
4. **证据胜过装饰**：优先展示岗位、步骤、结果、原因和时间；不使用无信息价值的色条、编号或口号。
5. **用户始终掌控**：暂停、继续、确认和失败恢复应容易找到；高风险动作必须清楚说明影响。

## 2. 视觉方向

### 2.1 色彩

- 页面背景：浅中性灰；内容表面：白色。
- 主文字使用近黑色，次要文字使用中性灰。
- 品牌与主要操作只使用低饱和青绿色。
- 红、黄、绿仅表达危险、警告和成功，不作为装饰色。
- 常规容器使用 1px 边框，不使用阴影；阴影仅允许出现在浮层、菜单和对话框。
- 禁止渐变背景、金色装饰条、大面积深蓝色卡片和多种强调色竞争。

### 2.2 字体与字号

- 中文与界面正文使用系统无衬线字体；代码、URL、时间和技术标识可使用等宽字体。
- 页面标题：24/32px，字重 600。
- 区块标题：20/28px，字重 600。
- 正文：14/20px；较长说明可使用 16/24px。
- 辅助信息：12/16px，不得为了“精致”缩小到难以阅读。
- 不使用全大写英文眉题作为常规层级；必要的技术标签应短、少、弱化。

### 2.3 间距与圆角

- 所有间距取自 4px 基础刻度：4、8、12、16、24、32、40、48。
- 常规控件圆角 6px，卡片和浮层 8px，状态胶囊可使用完全圆角。
- 页面内容最大宽度 1200px，避免超宽屏上形成长行文本。
- 左侧导航标准宽度 224px；窄屏应折叠为顶部导航或抽屉。

## 3. 页面骨架

```text
┌─ 导航 224px ─┬─ 顶栏 56px：页面标题 / 系统状态 / 当前主操作 ─────┐
│              ├───────────────────────────────────────────────┤
│ 5 个以内入口  │ 内容区：max-width 1200px，按任务优先级纵向排列     │
│              │                                               │
│ 连接与隐私状态 │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- 顶栏标题只描述当前页面，不使用巨幅宣传语。
- 首屏先放当前任务、真实进度和需要用户处理的事项，再放历史数据。
- 同一层级不要同时出现“卡片套卡片”；最多一层容器边界。
- 列表优先使用行、分组和留白，仅在内容确实独立时使用卡片。

## 4. 核心组件规则

### 按钮

- 每个区块最多一个实心主按钮。
- 主按钮文案使用“动词 + 对象”，例如“继续投递”“保存简历”。
- 危险按钮不得复用品牌色；必须使用危险样式并说明后果。
- 禁用状态同时提供原因，不能只降低透明度。

### 表单

- 标签始终可见，不以 placeholder 替代字段名。
- 错误信息紧邻字段，并说明如何修复。
- 自动保存必须显示最后保存时间；手动保存必须有明确成功状态。

### 状态与进度

- 使用小型 Badge 表示静态状态，使用进度条或时间线表示连续过程。
- “已完成”必须来自可验证结果；不能因为动作已发出就提示成功。
- 暂停时展示暂停原因、已完成数量和可继续入口。

### 空状态

- 一句话说明为什么为空。
- 只提供一个最可能的下一步，不放插画或营销文案填充空间。

### 对话框与 Toast

- 对话框只用于需要阻断当前流程的决定。
- Toast 只提示轻量结果；关键信息必须保留在页面状态中。

## 5. JobDeck 的唯一视觉签名

Agent 实时任务时间线是整个产品唯一可以更强表达的区域。它应展示：

- 当前目标；
- 正在观察、规划、执行或验证的步骤；
- 使用的工具和结果摘要；
- 完成数量与目标数量；
- 暂停原因和下一步。

时间线可以使用品牌青绿色强调当前节点，其余页面保持克制。不要再用大标题、装饰色条或复杂卡片制造“AI 感”。

## 6. 动效与无障碍

- 常规状态变化 120ms，浮层 180ms；只动画透明度和位移。
- 遵循 `prefers-reduced-motion`，减少动效时立即切换状态。
- 所有交互必须可键盘访问并有清晰的 `:focus-visible` 焦点环。
- 正文与背景对比度至少 4.5:1，大字号至少 3:1。
- 不只依赖颜色表达状态；配合文字、图标或形状。
- 图标按钮必须有可访问名称。

## 7. 禁止模式

- 页面主标题超过 32px。
- 为装饰使用全大写英文眉题、序号矩阵或宽色条。
- 一个区块出现两个以上实心主按钮。
- 普通容器使用阴影、渐变或大面积深色填充。
- 三层以上卡片嵌套。
- 把所有内容都装进有边框的卡片。
- 使用 9px、10px 正文或依赖极低对比度制造层级。
- 成功提示早于结果验证。

## 8. 代码约束

- Web token 源：`web/design-tokens.css`。
- Chrome 扩展 token 镜像：`extension/design-tokens.css`。
- 两份文件必须逐字一致，并在对应 HTML 中先于页面 CSS 加载。
- 新 CSS 必须使用 `--jd-*` token；旧变量只能作为迁移期别名存在。
- 修改 token 或基础规则时必须运行 `npm run check`。

## 9. 评审清单

- [ ] 首屏能在 5 秒内看懂当前任务与下一步。
- [ ] 每个区块最多一个实心主按钮。
- [ ] 颜色、字号、间距和圆角来自 token。
- [ ] 失败、暂停、完成都由可验证状态驱动。
- [ ] 没有无意义的眉题、编号、色条、渐变或阴影。
- [ ] 键盘焦点、窄屏和减少动效模式可用。
- [ ] Web 与扩展 token 校验通过。
